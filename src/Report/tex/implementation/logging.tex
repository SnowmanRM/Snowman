\section{Logging}
Complex software needs to log what is happening, to simplify the understanding
of what happend if things doesnt work as expected. It is also needed to
document what is done, in case someone would need to see if an update ran or
simmilar. As \snowman \ is slightly more than a couple of small scripts, we need
to think about logging of the internal workings.

For the logging of internal events in both the \snowman{}-client, and the
\snowman{}-server, we decided to use the standard python logging libraries.
These library allows us to log events with a certain severity inside our code,
depending on how important these events are. The logger would then log from
which modules the events appear, the time an event happens, and a message
describing the event. Debug, Info, Warning, Error and Critical is the default
logging-severities, sorted in an ascending order. 

The logger can then get assigned handlers, which decides where to store the
logged events. \snowman \ is by default using one handler, writing events to a
file. The configurationfile for \snowman \ decides where this file is stored,
and which severeties is stored. Under normal operation, it is recommended to not log
the debug-messages, as they should not be needed, and therfore only use
diskspace.

The python logging facilities are configurable, and flexible. If future needs
would require some events to be stored in a database, or send an sms for that
matter, the only thing that would be needed to be done is to add a new handler.
