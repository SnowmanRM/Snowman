\subsection{Saving}

During early versions of the update code it was discovered that the saving of
changes to the central database needed some extra attention. The first versions
of \snowman \ saved every rule individually after a change was found and the
objects was updated. This turned out to be a big bottleneck, as updates could
take hours on lower end hardware.

A new approach was therefore implemented and now we store everything into
memory while parsing, and only start to save changes into the database when everything
has been parsed. As some of the objects is referring to other objects in the
database through foreign-keys, it is vital to store the objects depending on
other objects after the objects they depend on is stored. A safe order to save
them has been identified and the objects are saved in this order:
\begin{enumerate}
  \item Generators
  \item Classifications
  \item Reference-types
  \item RuleSets
  \item Rules
  \item RuleReferences
  \item Suppresses
  \item Filters
\end{enumerate}

For every point in the list above the procedure is more or less the same.
First, the objects recieved is attempted to be extracted from the database. The
response from the database lets us identify which objects are new and which are
changed. The changed objects can be updated and saved individually before all
the new objects are constructed and everything finally gets inserted into the
database in one bulk operation.
