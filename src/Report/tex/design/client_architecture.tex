\subsection{Architecture}

The MVC architecture for the client can be seen in figure
\ref{fig:client_architecture}.

\begin{figure}[h]
	\includegraphics[width=130mm]{./img/Client-MVC.png}
	\caption{Client Architecture}
	\label{fig:client_architecture}
\end{figure}

The update handler of the client has both an XML-RPC Client and an XML-RPC
Server. The XML-RPC Client is used to connect to the central server to do a
rule synchronisation. The XML-RPC Server is here so that the central server can
connect to the client and check to see if the client is active or to order
the client to perform rule syncronisation.

As the client should be as lightweight as possible and the only aspect we
need from any framework is a simple database connection and abstraction
layer, so we have decided to not use \django{} for the client. Instead we use
the database ORM \cite{database_orm} for Python called SQL-Alchemy \cite{sql_alchemy}, which is
much more lightweight than \django{} for this purpose.

The client also contains a file creator which takes the rules objects in the
database and generates the files Snort needs in the format Snort needs them in.
