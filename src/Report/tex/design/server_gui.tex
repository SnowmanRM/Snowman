\subsection{User Interface}
The main user interface for \snowman{} is the web interface. It is based on
\django{}'s template system which generate the HTML that is displayed in the
web browser on the user's computer. 

\subsubsection{URLs}

The first step of serving a page to a user is a HTTP request for a specific
page. The pages are uniquely identified by URLs, such as '<server
address>/web/rules/'.

The URLs are structured in a logical manner, where everything in the
web interface is found under /web/, everything regarding the administration of
rules is found under /web/rules/ and so on. The URLs might contain dynamic
data, like pagenumbers (ie: /web/rules/rules/page/3/ which will give you the third
page of the rule-list), so that dynamic content can be loaded when
needed.

\django{} uses the URLs to identify which view the requested url corresponds to.
When a view is identified the request is passed to the corresponding view.

\subsubsection{Views}

The views is the part of the user interface that collects the required data
from the models-layer and then generates a response to the web client. The
response can contain a full web page, or just a small subset of one.

The typical steps a view makes, to generate a response would be:
\begin{enumerate}
  \item Collect the requiered data from the database(s) using the \django{}
  models.
  \item Hand the collected data, and a template, to the template-engine to
  generate the HTML representing the webpage the user want.
  \item Send the created web page as a response to the user.
\end{enumerate}

The view system decides what to show and then lets the template system decide
how to show it. The view system in and of itself is not creating any HTML or
simmilar. It solely creates data structures.

If the request was for raw data and not a webpage, step 2 in the list above
might be skipped, and instead return the data as some form of recognizable data
structure in step 3.

If errors occur in the view system, appropriate exceptions can be raised that
tell \django{} to return an error code or an error page to the user instead of
what the user requested.

\subsubsection{Templates}

When the view system have prepared all the data, the template system takes over.
The job of the templates is to take the supplied data and inject it into
pre-made skeletons of HTML. This way, all the design/display parts of the
web interface is contained into one single and separate place, and that gives us
a very clear line between data and design.
