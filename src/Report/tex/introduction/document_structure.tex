\section{Document Structure}
\begin{itemize}[]
\item INTRODUCTION - Contains an overview and description of the project and
its goals.
\item EXISTING SOLUTIONS - Describes similar software and information relevant
to the project.
\item REQUIREMENTS SPECIFICATION - Describes the requirements and scope of the
software development.
\item CONCEPTS OF SNORT - Explains the basic concepts of \snort{}.
\item DESIGN - Details the architecture and design of the system.
\item IMPLEMENTATION - Describes how the system has been implemented.
\item SOFTWARE TESTING - A short description of how the system has been tested
and some of the practical problems the project has encountered.
\item PERFORMANCE ANALYSIS - Describes what and how we have
tested the system for performance.
\item RESULTS OF PERFORMANCE TESTING - Lists the results of the performance
testing.
\item ANALYSIS OF PERFORMANCE TESTING RESULTS - Contains an analysis and
concludes the findings of the performance tests.
\item CONCLUSIONS - Summarizes the findings in this report.
\item GROUP EVALUATION - The group evaluation of this project.
\item BIBLIOGRAPHY
\item APPENDICES - Some parts of the appendices are only available in Norwegian.
\end{itemize}


\subsection{Special Styles Used}
Software names are written in a different font throughout the
report, like so: \snowman{}. Source code is listed in an enclosed box with
syntax highlighting (Listing \ref{lst:example}). Source code can also appear in
the text with the same syntax highlighting as the listings, especially note
names of modules and classes which will appear as so:
\pythoninline{module}, \pythoninline{Class}.
