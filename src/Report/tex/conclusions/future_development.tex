\section{Future Development}
At the start of the project we were ambitious with our project goals and the
client had a long list of functionality they wanted implemented. While a large
chunk of the functionality made it to our latest version, we had to sacrifice some due to
time constraints. 

And that were the functions we put in the ``if time
permitting'' pile from the start, the ability to comment rules, the ability to
write new custom rules and to have some sort of way to check for errors in the
rules before they are distributed. There is, however, no problems adding these
features in future work, as we've strived to make the program modularized. 

There are also more optimization work that could be done to speed things
up, especially when it comes to fetching lists of rules.

The GUI could probably also benefit from more work, as it has a few quirks and
odd bugs. It would probably be beneficial to find some other way of doing
pagination, as the implementation in the current iteration is not optimal.
There's also some cosmetic improvements to be done to tighten up the looks,
there are a few places where theres too much clutter once you've navigated and
opened too many things.

 We also compiled an improvements list from our client on a few matters, which
 is available in appendix \cite{app:}.
